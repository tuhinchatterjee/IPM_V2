# Static findings: verified by reading the frozen code, independent of any run

These were found while mapping the execution path (P3), and each was re-checked by hand. **None
has been fixed.** The frozen AdvancedCockpit is unchanged. Each finding names the live signal the
certification counts, so the overnight run can confirm or refute its practical effect. Every
experiment's `ARCHITECTURE_FINDINGS.md` repeats this table with the live counts.

| ID | Severity | Layer | Finding | How it was verified | Live signal counted |
|---|---|---|---|---|---|
| S-01 | HIGH | ARCH_CONTRACT | The `finalize_response` disposition enum given to the model disagrees with the parser. | `provider_tools()` shows the model `["answer","partial","referral","clarification","unsupported"]` (from `contracts/finalize_response.schema.json`). The parser `contracts.py:56-58` accepts `answer, partial_answer, referral, clarification, unsupported, safe_failure`, and `contracts.py:1019-1024` raises `ANSWER_VALIDATION` for anything else. A schema-compliant `partial` is refused, and `partial_answer` is never offered. The frozen test `test_action_contract.py:186` asserts `partial_answer` is absent from the schema, so the mismatch is codified. | `answer.validated` rejections whose problems contain "disposition must be one of" |
| S-02 | MEDIUM | ARCH_CONTRACT | The answer-reserve instruction names a disposition that does not exist. | `orchestration.py:618` tells the model "Use the `cannot_answer` disposition", which is in neither the schema nor `DISPOSITIONS`. | runs that entered `answer_reserve` without an execution and then failed validation |
| S-03 | MEDIUM | ARCH_BUDGET | SDK retries are not disabled, so up to 3 HTTP attempts per paid call are invisible to the ledger. | `anthropic_provider.py:327-328` builds `anthropic.Anthropic(api_key, timeout)` without `max_retries`, and `with_options(timeout=…)` does not set it. In the pinned SDK (0.112.0), `anthropic._constants.DEFAULT_MAX_RETRIES == 2`, checked in the certification venv. `allow_retry=False` only disables the adapter's own loop (`:244`). | `model_calls.csv` `provider_retries` (from the harness's httpx pass-through) |
| S-04 | MEDIUM | ARCH_BUDGET | Each generation spends 3 or more provider attempts against a limit of 24. | `ledger.spend_provider_attempt()` is called in `provider.py:232` (`count_input`), `:332` (`_converse.send`) and `:497` (`ask`), and `count_input` runs twice when the output allowance is reduced. About 8 generations exhaust `provider_attempts=24` before `generation_attempts=12`. | runs ending `CALL_LIMIT`; `budget.provider_attempts` vs `generation_attempts` |
| S-05 | LOW | ARCH_ORCHESTRATION | Operator records redact every token count. | `run_store.redact()` (`run_store.py:1610`) replaces any key containing "token". `model.response_received` details and the stored `call_report` therefore hold `[redacted]` usage, and only `reservations.usage` keeps native counts. | detail bodies containing `[redacted]` |
| S-06 | LOW | ARCH_ORCHESTRATION | The model that actually served a call is never read. | `anthropic_provider.py:298` returns `model=chosen` (the requested id), and `message.model` is discarded. | `served_models` (harness SDK pass-through) vs `requested_model` |
| S-07 | LOW | ARCH_ORCHESTRATION | Assistant turns are persisted as Python `repr` strings. | `run_store.save_messages` applies `json.dumps(…, default=str)` to SDK block objects (`run_store.py:918`). | assistant `content` stored as a string |
| S-08 | LOW | TEST_HYGIENE | The frozen regression suite rewrites tracked files. | Running `tests/cockpit_v4` modifies five files under `docs/cockpit_v4/evidence/` (`dual_domain_performance`, `math_query_engine`, `overnight_analytical_benchmark`, `performance`, `saudi_release_fingerprint`). The harness records the diff and restores them from the frozen commit. | `artifacts/opus360/regression/*.json` |
| S-09 | LOW | ARCH_ORCHESTRATION | The process runs one worker thread, and each principal is limited to 2 active runs. | `app.py:176-186` starts a single `Worker.serve_forever` thread. `routes.py:328-335` returns 429 at 2 active runs per principal. Concurrency above 1 therefore queues, and above 2 is refused at admission. | `load_test.csv` `queue_wait_ms`, `admission_retries_429` |
| S-10 | LOW | TEST_HYGIENE | The Round H live-UAT capture read event fields that do not exist. | `scripts/cockpit_v4/live_uat.py:587-589` reads `e.created_at` / `e.body`, but `Event` has `occurred_at` / `detail_ref`. The Round H evidence file's event bodies were therefore empty. | n/a (quality of historical evidence) |

Also noted, not a defect: the `envelope.py` docstring says 120 s for analysis, but the code value
is 180 s (`config.ANALYTICAL_STANDARD_LIMITS`). The harness uses what the code does.
